Contributing ​

Thank you for your interest in contributing to SHAVIRA. This guide covers the development workflow, code quality standards, and conventions.

Prerequisites ​

  • Node.js 24 LTS
  • npm 10+
  • Docker and Docker Compose
  • Python 3.9+ (optional, for Python SDK work)

First-Time Setup ​

bash
git clone https://github.com/harbindersingh/security-ai-agent.git
cd security-ai-agent
npm install
cp .env.example .env

Running the Stack ​

With Docker (recommended) ​

bash
docker compose up --build

Without Docker (faster iteration) ​

Requires a PostgreSQL instance. Set DATABASE_URL in .env, then:

bash
npm run dev

This runs the API with tsx watch and the web app with Vite's dev server.

Development Workflow ​

  1. Create a feature branch: git checkout -b feature/your-feature-name
  2. Make your changes
  3. Run quality checks (see below)
  4. Submit a PR to main

Quality Gates ​

Before submitting a PR, all checks must pass:

bash
# TypeScript must compile clean
cd apps/api && npx tsc --noEmit
cd apps/web && npx tsc --noEmit

# Lint
npm run lint

# Unit + integration tests
npm run test

# E2E tests (requires Docker stack running)
npx playwright test

Code Standards ​

TypeScript ​

  • Strict mode enabled
  • ESM throughout ("type": "module")
  • No any types without justification
  • Zod schemas for all API request/response validation

Security Checklist ​

Every PR must satisfy:

  • No secrets, keys, or tokens in code
  • All user input validated at API boundary (Zod schemas)
  • No SQL injection vectors (parameterized queries only)
  • Auth enforced on all new routes
  • No new any types without justification

Adding API Routes ​

  1. Define the route in apps/api/src/app.ts
  2. Guard with authMiddleware (and requireAdmin if admin-only)
  3. Scope all queries to workspace_id
  4. Validate inputs with Zod
  5. Add tests

Adding Database Tables ​

  1. Add CREATE TABLE IF NOT EXISTS in apps/api/src/db/bootstrap.ts
  2. Include workspace_id column
  3. Seed reference data if needed
  4. Never alter existing columns — only add new ones

Testing Strategy ​

TypePurposeDatabase
UnitPure logic, no I/ONone
IntegrationFull HTTP + real DBPostgreSQL
E2EBrowser automationFull Docker stack

Commit Messages ​

  • Subject line: 50 characters max, imperative mood
  • Blank line after subject
  • Body: explain what and why, not how

Documentation ​

  • Write a PRD before starting feature work (see docs/prd/_template.md)
  • Update relevant user docs in docs/user/
  • Keep CLAUDE.md up to date with architectural changes

Process ​

SHAVIRA follows a phased SDLC: Discover > Define > Design > Build > Verify > Release > Retro. See the project CLAUDE.md for details on each phase and its quality gates.
