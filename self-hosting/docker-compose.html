Docker Compose Deployment ​

SHAVIRA is designed to be self-hosted. A single docker compose up gets the full platform running.

Architecture ​

┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   Web UI    │    │   API       │    │  PostgreSQL  │
│  (React)    │───▶│  (Express)  │───▶│    16        │
│  port 4173  │    │  port 4000  │    │  port 5432   │
└─────────────┘    └─────────────┘    └─────────────┘

Quick Start ​

bash
git clone https://github.com/harbindersingh/security-ai-agent.git
cd security-ai-agent
cp .env.example .env
docker compose up --build

Docker Compose File ​

The included docker-compose.yml defines three services:

api ​

  • Express 5 API server
  • Connects to PostgreSQL
  • Bootstraps schema and seeds demo data on first start
  • Health check: GET /api/health

web ​

  • Static React build served by a lightweight HTTP server
  • Built at image build time (not runtime)
  • No server-side rendering — pure static assets

db ​

  • PostgreSQL 16
  • Data persisted in a Docker volume
  • Schema created automatically by the API on startup

Production Considerations ​

Reverse Proxy ​

Place Nginx or Caddy in front for TLS termination:

nginx
server {
    listen 443 ssl;
    server_name shavira.yourcompany.com;

    location /api/ {
        proxy_pass http://localhost:4000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location / {
        proxy_pass http://localhost:4173;
    }
}

Database Backups ​

Schedule regular PostgreSQL backups:

bash
pg_dump -h localhost -U postgres shavira > backup-$(date +%Y%m%d).sql

Resource Requirements ​

ComponentCPUMemory
API0.5 vCPU512 MB
Web0.25 vCPU128 MB
PostgreSQL0.5 vCPU512 MB

Minimum total: 2 GB RAM, 2 vCPU.

Upgrading ​

bash
git pull
docker compose up --build -d

The API automatically applies schema migrations on startup.
