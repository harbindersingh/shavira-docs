Detection Rules ​

SHAVIRA uses Sigma-based detection rules to identify security issues in your AI traces. Rules are evaluated against ingested events and generate findings when matched.

Built-in Rules ​

SHAVIRA ships with four built-in detection rules:

RuleSeverityDescription
Prompt InjectionHighDetects common prompt injection patterns in user inputs
PII ExposureHighIdentifies personally identifiable information in model outputs
Excessive TokensMediumFlags traces with unusually high token consumption
Unauthorized ModelMediumDetects use of models not in the approved list

Built-in rules are read-only but can be toggled on/off.

Creating Custom Rules ​

  1. Navigate to Detections > Rules
  2. Click New Rule
  3. Fill in the rule editor:
    • Title — descriptive name
    • Description — what the rule detects and why
    • Severity — critical, high, medium, or low
    • Sigma YAML — the detection logic
    • ATT&CK IDs — optional MITRE ATT&CK technique mappings

Sigma YAML Format ​

Rules use the Sigma rule format. Required fields:

yaml
title: Detect Jailbreak Attempts
logsource:
  category: ai_trace
  product: shavira
detection:
  selection:
    payload|contains:
      - "ignore previous instructions"
      - "you are now"
      - "pretend you are"
  condition: selection
level: high

Required Fields ​

  • title — rule title (must match the title field in the editor)
  • logsource — must include category and product
  • detection.condition — the boolean logic combining selections

Detection Logic ​

Sigma supports field modifiers:

ModifierDescription
`contains`
`startswith`
`endswith`
`re`
`all`

Validating Rules ​

Click Validate before saving to check your Sigma YAML for syntax errors. The validator checks:

  • YAML is well-formed
  • Required fields (title, logsource, detection.condition) are present
  • Detection logic is syntactically valid

Testing Rules ​

Click Test to run your rule against recent traces. The test:

  1. Searches the last 100 matching ingest events
  2. Returns the match count and up to 10 sample matches
  3. Each match shows the trace ID, event type, timestamp, and matched field

This helps verify your rule catches what you expect before enabling it.

Version History ​

Every rule update is versioned. Click Versions to see the full history with diffs. Each version records:

  • Version number (auto-incremented)
  • Sigma YAML at that version
  • Title, description, ATT&CK IDs, severity
  • Who made the change and when

Exporting Rules ​

Export rules in multiple formats:

  • Sigma — standard Sigma YAML (default)
  • JSON — structured JSON representation
  • YAML — full rule metadata as YAML

Use GET /api/v2/detection-rules/:id/export?format=sigma or the export button in the UI.

Toggling Rules ​

Enable or disable any rule (including built-ins) without deleting it. Disabled rules stop generating new findings but retain their configuration and version history.
