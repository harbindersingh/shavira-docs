Findings & Workflows ​

Findings represent security issues detected in your AI traces. SHAVIRA provides a workflow system for triaging, assigning, and resolving findings.

Finding Structure ​

Each finding contains:

FieldDescription
TitleDescriptive name of the security issue
Severitycritical, high, medium, or low
StatusCurrent workflow state
AssigneeTeam member responsible for triage
Detection artifactsSigma rules, SIEM queries, ATT&CK mappings
Trace linkAssociated trace for investigation
ProjectProject where the finding was detected
CommentsDiscussion thread

Status Workflow ​

Findings progress through four states:

Open → Investigating → Resolved
                    → False Positive
StatusMeaning
OpenNew finding, not yet triaged
InvestigatingUnder active investigation
ResolvedIssue confirmed and remediated
False PositiveNot a real issue

When a finding is resolved or marked as false positive, SHAVIRA records who resolved it and when.

Filtering Findings ​

Use the status filter chips at the top of the findings view to show/hide findings by status. Combine with:

  • Severity filter — focus on critical/high issues first
  • Search — fuzzy search on finding titles
  • Assignee — see what's assigned to you or unassigned
  • Project — scope to a specific project

Assigning Findings ​

  1. Click a finding to open the detail panel
  2. Use the Assignee dropdown to select a team member
  3. The assignee receives the finding in their filtered view

Unassign by selecting the empty option from the dropdown.

Adding Comments ​

Open a finding's detail panel and switch to the Comments tab:

  1. Type your comment in the text area
  2. Click Post
  3. Comments appear in chronological order with author name and timestamp

Use comments to document investigation steps, share context, or request input from teammates.

Bulk Actions ​

Select multiple findings using the checkboxes, then use the bulk action toolbar to:

  • Set status — change all selected findings to a status
  • Assign — assign all selected findings to a user

Bulk actions are audit logged with the count of affected findings.

Audit Trail ​

All finding actions are logged:

EventLogged Fields
finding.status_changedOld status, new status, user
finding.assignedPrevious assignee, new assignee
finding.commentedComment author, finding ID
finding.bulk_updateAction type, count, user
