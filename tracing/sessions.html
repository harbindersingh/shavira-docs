Sessions & End Users ​

Sessions group related traces from multi-turn conversations. End users track which external users generated traces.

Sessions ​

A session is a logical grouping of traces that share the same sessionId. This typically represents a single conversation or interaction flow.

How Sessions Work ​

  1. Your SDK sets a sessionId on each trace (e.g., a conversation ID)
  2. SHAVIRA groups all traces with the same session ID
  3. The Sessions view shows aggregated stats per session

Session Summary ​

Each session displays:

MetricDescription
Session IDThe shared identifier
UserEnd user who initiated the session
TracesNumber of traces in the session
EventsTotal event count
FindingsSecurity findings detected
Total costAggregated cost across all traces
Total tokensSum of input + output tokens
Top modelMost-used model in the session
First seenTimestamp of earliest trace
Last seenTimestamp of most recent trace

Searching Sessions ​

Filter sessions by:

  • Session ID — substring search (case-insensitive)
  • User — filter by end user ID
  • Project — restrict to a specific project

Results are paginated with configurable page size (up to 200 per page).

Session Events ​

Click a session row to view all events in chronological order. Each event shows the trace ID, span ID, event type, timestamp, provider, model, and cost.

End Users ​

End users represent the external people using your AI application. Set the endUserId field in your SDK to track who triggers each trace.

End User List ​

The end users view shows distinct users with per-project aggregation. The same user appearing in two different projects shows as two separate rows.

Each user entry displays:

  • User ID
  • Project
  • Trace count
  • Total cost
  • First and last seen timestamps

Setting User Identity ​

python
@observe_route(telemetry, trace_name="chat-flow")
async def chat(request: Request):
    request.state.security_user_id = "user@example.com"
    # ...
typescript
await sdk.trace('my-trace').start({
  userId: 'user@example.com',
  sessionId: 'conv-123',
  // ...
})

SDK Field Validation ​

Both sessionId and userId are validated:

  • Must be a non-empty string after trimming
  • Maximum 256 characters
