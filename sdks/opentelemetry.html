OpenTelemetry Integration ​

SHAVIRA accepts OpenTelemetry spans via the OTLP/JSON protocol. This lets you send traces from any OTel-instrumented application or collector.

How It Works ​

SHAVIRA exposes a POST /v1/traces endpoint that accepts OTLP/JSON payloads. Each OTel span is converted into a SHAVIRA ingest event with:

  • otel_trace_id and otel_span_id preserved for correlation
  • Trace IDs prefixed with otel- to avoid collisions with SDK traces
  • gen_ai.* attributes mapped to provider/model fields
  • shavira.* attributes mapped to project, session, and user fields

Direct API Ingest ​

Send spans directly to SHAVIRA without a collector:

bash
curl -X POST http://localhost:4000/v1/traces \
  -H "Authorization: Bearer shv_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "resourceSpans": [{
      "resource": {
        "attributes": [
          { "key": "service.name", "value": { "stringValue": "my-app" } }
        ]
      },
      "scopeSpans": [{
        "spans": [{
          "traceId": "abc123def456",
          "spanId": "span001",
          "name": "llm-call",
          "kind": 3,
          "startTimeUnixNano": "1700000000000000000",
          "endTimeUnixNano": "1700000001000000000",
          "attributes": [
            { "key": "gen_ai.system", "value": { "stringValue": "openai" } },
            { "key": "gen_ai.request.model", "value": { "stringValue": "gpt-4o" } },
            { "key": "gen_ai.usage.input_tokens", "value": { "intValue": "150" } },
            { "key": "gen_ai.usage.output_tokens", "value": { "intValue": "80" } }
          ]
        }]
      }]
    }]
  }'

OTel Collector Configuration ​

Configure the OpenTelemetry Collector to forward spans to SHAVIRA:

yaml
# otel-collector-config.yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

exporters:
  otlphttp:
    endpoint: http://shavira-api:4000
    headers:
      Authorization: "Bearer shv_your_api_key"

service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp]

Recognized Attributes ​

gen_ai.* Attributes ​

SHAVIRA maps these standard GenAI semantic conventions:

AttributeMaps To
gen_ai.systemprovider
gen_ai.request.modelmodel
gen_ai.usage.input_tokensinputTokens
gen_ai.usage.output_tokensoutputTokens
gen_ai.usage.total_tokenstotalTokens

shavira.* Attributes ​

Custom attributes for SHAVIRA-specific fields:

AttributeMaps To
shavira.project_idprojectId
shavira.session_idsessionId
shavira.user_iduserId
shavira.environmentenvironment

Authentication ​

The /v1/traces endpoint requires an API key:

Authorization: Bearer shv_your_api_key

Create API keys in Settings > API Keys. Keys can be scoped to a specific project — all traces ingested with a project-scoped key are automatically tagged to that project.

WARNING

The OTel endpoint currently supports JSON format only (Content-Type: application/json). Protobuf support (application/x-protobuf) is planned.

Supported Payload Format ​

The endpoint accepts the standard OTLP/JSON TracesRequest format with resourceSpans containing scopeSpans and spans.

Real-time Integration ​

OTel-ingested traces are published to the SSE event bus, so they appear in real time on the dashboard just like SDK traces.
