Findings API ​

Query, triage, and manage security findings.

GET /api/findings ​

Search findings with filtering.

  • Auth: Authenticated
  • RBAC: Non-admins see only findings in accessible projects + workspace-level findings

Query Parameters ​

ParamTypeDefaultDescription
searchstring—Fuzzy search on title
severitystring—critical, high, medium, low
statusstring—open, investigating, resolved, false_positive
assigneeIdstring—Filter by assignee user ID
projectIdstring—Filter by project
limitnumber500Max results (1–5000)

Response ​

json
[
  {
    "id": "finding-001",
    "title": "Prompt Injection Detected",
    "severity": "high",
    "status": "open",
    "assigneeId": null,
    "assigneeName": null,
    "assigneeEmail": null,
    "projectId": "proj-001",
    "traceId": "trace-001",
    "updatedAt": "2024-01-15T10:30:00Z",
    "detectionArtifacts": { ... }
  }
]

Example ​

bash
curl -H "Authorization: Bearer shv_your_key" \
  "http://localhost:4000/api/findings?status=open&severity=high"

PATCH /api/findings/:id/status ​

Update a finding's status.

  • Auth: Authenticated
  • Audit logged: finding.status_changed

Request Body ​

json
{
  "status": "investigating"
}
FieldTypeValues
statusstringopen, investigating, resolved, false_positive

Response ​

json
{
  "finding": { ... },
  "oldStatus": "open"
}

When transitioning to resolved or false_positive, the API automatically records resolved_at and resolved_by.

Example ​

bash
curl -X PATCH http://localhost:4000/api/findings/finding-001/status \
  -H "Cookie: shv_token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "status": "investigating" }'

PATCH /api/findings/:id/assign ​

Assign a finding to a user.

  • Auth: Authenticated
  • Audit logged: finding.assigned

Request Body ​

json
{
  "assigneeId": "user-001"
}

Set assigneeId to null to unassign.

Response ​

json
{
  "finding": { ... },
  "previousAssigneeId": null
}

POST /api/findings/:id/comments ​

Add a comment to a finding.

  • Auth: Authenticated
  • Audit logged: finding.commented

Request Body ​

json
{
  "body": "Investigated — this appears to be a legitimate jailbreak attempt."
}

Response ​

json
{
  "id": "comment-001",
  "findingId": "finding-001",
  "authorId": "user-001",
  "authorName": "Jane Smith",
  "body": "Investigated — this appears to be a legitimate jailbreak attempt.",
  "createdAt": "2024-01-15T11:00:00Z"
}

GET /api/findings/:id/comments ​

List all comments on a finding.

  • Auth: Authenticated

Response ​

json
[
  {
    "id": "comment-001",
    "findingId": "finding-001",
    "authorId": "user-001",
    "authorName": "Jane Smith",
    "body": "...",
    "createdAt": "2024-01-15T11:00:00Z"
  }
]

Comments are sorted by createdAt ascending.

POST /api/findings/bulk ​

Bulk update multiple findings.

  • Auth: Authenticated
  • Audit logged: finding.bulk_update

Request Body ​

json
{
  "findingIds": ["finding-001", "finding-002", "finding-003"],
  "action": "status",
  "status": "resolved"
}
FieldTypeDescription
findingIdsstring[]Array of finding IDs
actionstringstatus or assign
statusstringRequired if action=status
assigneeIdstring | nullRequired if action=assign

Response ​

json
{
  "updated": 3
}

Example ​

bash
# Bulk assign findings
curl -X POST http://localhost:4000/api/findings/bulk \
  -H "Cookie: shv_token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "findingIds": ["finding-001", "finding-002"],
    "action": "assign",
    "assigneeId": "user-001"
  }'
