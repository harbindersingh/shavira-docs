Send Your First Trace ​

Instrument an AI app and see it in SHAVIRA in about 5 minutes. Pick your language below — the flow is the same everywhere: install the SDK → point it at SHAVIRA with an API key → wrap the code that calls your model → open the Traces view.

Prerequisites ​

  • SHAVIRA running locally (Docker Setup) — the API listens on http://localhost:4000
  • A workspace API key. Create one in the UI under Settings → API Keys. Ingest keys are prefixed shv_ and are sent as Authorization: Bearer shv_....

Do I need a key locally?

POST /api/ingest and POST /v1/traces require a valid shv_ key. Generate one from the dashboard first, then export it as shown below.

1. Configure the environment ​

Every SDK reads the same variables. The SDK is a no-op when disabled, so leaving SECURITY_SDK_ENABLED unset is safe in environments where you don't want telemetry.

bash
export SECURITY_SDK_ENABLED=true
export SECURITY_SDK_BASE_URL=http://localhost:4000
export SECURITY_SDK_API_KEY=shv_your_workspace_key
export RUNTIME_ENVIRONMENT=local
export SERVICE_NAME=my-first-app

2. Instrument your app ​

Python ​

Install the SDK:

bash
pip install shavira

The Python SDK auto-instruments installed LLM clients (OpenAI, Anthropic, Google Gemini / Vertex AI, and Bedrock via the Converse API) the moment telemetry is enabled. Wrap the request you want to trace in trace_context, call your model as usual, and token usage is captured automatically on the generation span:

python
from openai import OpenAI
from shavira import SecurityTelemetry

telemetry = SecurityTelemetry.from_env(service_name="my-first-app")
client = OpenAI()

with telemetry.trace_context(
    trace_name="chat",
    user_id="user@example.com",       # the END user, not a SHAVIRA account
    session_id="session-123",         # optional — groups multi-turn traces
    input_payload={"prompt": "Hello, SHAVIRA!"},
) as trace:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "Hello, SHAVIRA!"}],
    )
    # The OpenAI call above is auto-captured as a priced generation span.

For providers you call yourself (or any custom step), open a span and attach usage explicitly — this is exactly how the sample app traces Bedrock:

python
with telemetry.trace_context(trace_name="chat", user_id="user@example.com") as trace:
    with trace.span("call_llm", {"phase": "generation", "provider": "bedrock", "model": model}) as span:
        response = bedrock.converse(modelId=model, messages=[...])
        usage = response.get("usage", {})
        span.set_usage(
            provider="bedrock",
            model=model,
            prompt_tokens=usage.get("inputTokens"),
            completion_tokens=usage.get("outputTokens"),
        )

Instrument a FastAPI route with the observe_route decorator. It derives the end-user, session, route, and input payload from the request automatically:

python
from fastapi import Depends, FastAPI, Request
from shavira import SecurityTelemetry, observe_route

app = FastAPI()
telemetry = SecurityTelemetry.from_env(service_name="my-first-app")


def extract_user(request: Request) -> str:
    request.state.security_user_id = "user@example.com"
    request.state.security_metadata = {"provider": "openai", "model": "gpt-4o-mini"}
    return request.headers.get("authorization", "")


@app.post("/chat")
@observe_route(telemetry, trace_name="chat-flow")
async def chat(body: dict, request: Request, token: str = Depends(extract_user)):
    # your LLM logic here — auto-instrumented client calls are captured as spans
    return {"response": "Hello from SHAVIRA!"}

Verify connectivity first

Before wiring up real traffic, emit a one-off startup trace and print the SDK diagnostics:

python
telemetry = SecurityTelemetry.from_env(service_name="my-first-app")
print(telemetry.emit_startup_trace(route="/startup"))
# {"ok": true, "trace_id": "...", "base_url": "...", "last_success_operation": "trace.start", ...}

TypeScript ​

bash
npm install @shavira/sdk

The TypeScript SDK is a thin, explicit client — you create a trace, then emit spans, events, and cost records against it:

typescript
import { SecurityAgentSdk } from '@shavira/sdk'

const sdk = new SecurityAgentSdk({
  baseUrl: 'http://localhost:4000',
  apiKey: process.env.SECURITY_SDK_API_KEY, // shv_...
})

const traceId = crypto.randomUUID()
const trace = sdk.trace(traceId)

// Open the trace
await trace.start({
  trace_name: 'chat-flow',
  user_id: 'user@example.com',
  session_id: 'session-123',
  environment: 'local',
  service_name: 'my-ts-app',
})

// Record the model call as a span with token usage
await trace.spanStart('call_llm', { phase: 'generation', provider: 'openai', model: 'gpt-4o-mini' })
await trace.spanEnd('call_llm', {
  phase: 'generation',
  status: 'completed',
  provider: 'openai',
  model: 'gpt-4o-mini',
  prompt_tokens: 42,
  completion_tokens: 18,
})

// Or record cost/usage on its own
await trace.cost({
  provider: 'openai',
  model: 'gpt-4o-mini',
  prompt_tokens: 42,
  completion_tokens: 18,
})

curl ​

Every SDK ultimately POSTs the same event envelope to POST /api/ingest. You can send one by hand:

bash
# 1. Open a trace
curl -X POST http://localhost:4000/api/ingest \
  -H "Authorization: Bearer $SECURITY_SDK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "trace.start",
    "traceId": "trace-001",
    "sessionId": "session-123",
    "userId": "user@example.com",
    "timestamp": "'"$(date -u +%Y-%m-%dT%H:%M:%SZ)"'",
    "payload": { "trace_name": "chat", "service_name": "my-first-app", "environment": "local" }
  }'

# 2. Close a generation span with token usage (drives cost)
curl -X POST http://localhost:4000/api/ingest \
  -H "Authorization: Bearer $SECURITY_SDK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "span.end",
    "traceId": "trace-001",
    "spanId": "call_llm",
    "timestamp": "'"$(date -u +%Y-%m-%dT%H:%M:%SZ)"'",
    "payload": { "phase": "generation", "status": "completed", "provider": "openai", "model": "gpt-4o-mini", "prompt_tokens": 42, "completion_tokens": 18 }
  }'

A successful ingest returns 202 { "accepted": true }.

Already using OpenTelemetry?

If your app emits OTLP, point your exporter at POST /v1/traces (OTLP/JSON) with the same shv_ key instead of using an SDK. See OpenTelemetry Integration.

3. See your first trace ​

Open http://localhost:4173 and go to Traces. Your trace appears with its service name, environment, provider/model, cost, and status. Filter by event type, service, or user with the facet sidebar.

Click a trace row to open the trace detail, where you can inspect the span timeline, per-span metadata, token usage, and resolved cost.

Zoom back out to the Dashboard for the roll-up: total spend, cost by model and project, and the most recent activity across the workspace.

What SHAVIRA captures ​

SignalSource
Route / trace nameThe wrapped function or HTTP request
Input payloadPrompt or request body you pass in input_payload
Runtime identityservice_name, environment, instance_id (auto-derived)
End-user & sessionuser_id / session_id you attach to the trace
Token usageAuto-captured from instrumented clients, or via set_usage / cost
CostResolved from usage against synced model pricing
Latency & statusMeasured by the SDK around each span

Try the sample app ​

The repo ships a runnable reference, examples/python-provider-matrix, that exercises real traces, tool-call spans, and cost across Gemini, Vertex AI, OpenAI, Anthropic, and Bedrock:

bash
# Installs the example and pulls the published `shavira` SDK as a dependency
pip install -e examples/python-provider-matrix

provider-matrix run --provider openai --mode real     # real provider call
provider-matrix run --provider anthropic --mode synthetic  # no key needed
provider-matrix run --scenario matrix                 # all providers, one session

Each run generates a session ID so every provider trace groups together in Sessions. It's the best way to see a full multi-span DAG (draft_sql_query → verify_sql_query → assemble_provider_input → call_llm → validate_provider_response) end to end.
